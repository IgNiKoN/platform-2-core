# Серверы Platform 2.0

**Сейчас:** «План/Факт» подключён к общему self-hosted Supabase `https://api.rbi-q.ru` (ADR-061, ADR-061a, ADR-064). Адрес и публичный anon-ключ Platform 2.0 — в `js/services/config.service.js`, ключи `P2_SUPABASE_URL` / `P2_SUPABASE_ANON_KEY`.

**Сборка «разработка / выпуск» (P2-0013)** — один переключатель `var APP_BUILD` в `js/services/config.service.js` (его же читает кэш приложения `sw.js`):

| | `'dev'` — в репозитории всегда, GitHub Pages | `'release'` — сервер владельца вместо старой версии |
|---|---|---|
| Облако старого Quality (`SUPABASE_URL` / `KEY`, вход по PIN, синхронизация) | пусто — выключено | тот же сервер и тот же публичный ключ, что у Platform 2.0 |
| Локальная база на устройстве | `PLATFORM2_DB` | `RBI_QUALITY_DB` (черновики, фото и неотправленные отчёты людей на месте) |
| Кэш приложения | `platform2-v…` (кэши старого приложения на общем адресе не трогает) | `rbi-quality-v…` (старые `rbi-quality-*` заменяются при обновлении) |

В разработке облако Quality выключено намеренно: копия и старое приложение на одном адресе `ignikon.github.io` иначе делили бы локальную базу и могли писать в боевые таблицы Quality.

## Как применять миграции

Каждую — только по явному разрешению владельца, после снэпшота сервера: выполнить `NNN_up.sql` в SQL Editor сервера. Повторное применение безопасно (`if not exists`, `or replace`). Откат — `NNN_down.sql` в обратном порядке (005 → 001); откат 005 оставляет созданные роли и назначения (данные) и строки журнала, удаляет функции экранов; откат 002 теряет назначения ролей, откат 004 — журнал и суммы. **Откат на копии базы не проверялся** (см. `TECH_DEBT.md`).

## Выпуск Platform 2.0 вместо старой версии (P2-0013)

Выкладывает владелец, когда решит. Боевая база людей не меняется — меняются только файлы на сервере.

1. Собрать модули: `npm run build:planfact && npm run build:company && npm run build:platform && npm run build:platform-admin`.
2. Сборка «выпуск» в отдельную папку вне репозитория: `node scripts/make-release.mjs ../platform2-release` — копия файлов приложения (без исходников, тестов, регламента, миграций, `.env*` и `.map`), в копии `APP_BUILD = 'release'`. Репозиторий остаётся `'dev'`.
3. Перед выкладкой — проверка на тестовом коде проекта `TEST-P2` (не на рабочих проектах): открыть сборку на одном адресе со старой версией → вкладка «Имя, код проекта и PIN» → вход → отчёт → синхронизация → отчёт виден в старом приложении; черновик, сделанный в старой версии, на месте.
4. Сохранить копию текущих файлов сервера (для отката), выложить содержимое папки вместо них.
5. У людей: приложение обновится (кнопка «Обновить» / обновить страницу дважды). Вход по PIN — как раньше (вкладка «Имя, код проекта и PIN»); кто уже был подключён по PIN — сразу попадает в «Качество» без экрана входа; локальная база `RBI_QUALITY_DB` та же.
