# Перенос данных РБИ в Платформу 2.0 (P2-0027)

Старое приложение РБИ (вход по PIN, раздел `public`, публичные бакеты) → компания «RBI» Платформы 2.0 (раздел `quality`, закрытые бакеты `quality-*`, вход по почте). Старое приложение и его данные **только читаются**: перенос — копия.

## Что переносится

- **Записи:** все таблицы, которые есть и в `public`, и в `quality` (53 = `TABLES` из `scripts/gen-quality-schema.mjs` без двух ниже), строки старого проекта `rbi-test` (и строки без кода проекта). Проект `rbi-work` пустой, не сопоставлен — не переносится.
- **Не переносятся:** готовые отчёты — `shared_reports`, `shared_report_snapshots`, бакет `reports` (решение владельца: генерируются заново; удаление со старого сервера — отдельно, руками владельца, с архивом).
- **Файлы:** все файлы бакетов `construction-defects`, `construction-plans`, `custom-assets`, `inspection-photos`, `library-*` → `quality-<бакет>/<id компании>/<старый путь>`.
- **id записей сохраняются** (ключи `quality` — по компании). Код проекта `rbi-test` → id объекта ядра «Объекты RBI» (в `project_code` и внутри данных записи — `"project_code"`, `"projectCode"`). Ссылки `…/object/public/<бакет>/…` → `…/object/public/quality-<бакет>/<компания>/…`; `storage_path` — с компанией. PIN (`pin_hash`) не переносится.
- **Люди:** `quality.rbi_transfer_people` (старый профиль → почта → учётка). Сопоставленному человеку проставляется автор записей `core_created_by` и ссылки на учётку; старый профиль остаётся со старой учёткой (у человека свой профиль создаёт новое приложение при входе — 031b). Несопоставленные — автор пусто, имя в записи сохраняется.

## Объекты в базе (миграции 031, 031a, 031b, 031c)

| Объект | Назначение |
|---|---|
| `quality.rbi_transfer_projects` | старый код проекта → объект ядра компании |
| `quality.rbi_transfer_people` | старый профиль → почта → учётка |
| `quality.rbi_transfer_files` | файлы к копированию / скопированные / ошибки |
| `quality.rbi_transfer_runs` | журнал запусков (что сколько строк) |
| `quality.rbi_transfer_run(компания, объект)` | перенос; объект — ключ объекта РБИ (только проверки, пункты, фото, задачи), `null` — всё. Повтор — только новые строки |
| `quality.rbi_transfer_verify(компания, объект)` | сверка: строк старое (все / подходящие) = новое по каждой таблице; ссылки на старые бакеты; файлы |
| `quality.rbi_transfer_public_fingerprint()` | отпечаток `public` и бакетов РБИ (строк и md5) — до = после |
| `quality.rbi_transfer_clear(компания)` | удалить все строки компании в `quality` (до дня переключения в «RBI» работает только перенос) |

Все функции и таблицы закрыты для `anon`/`authenticated`; вызываются в SQL Editor (роль `postgres`). `service_role` видит только список файлов.

## Как запускать в SQL Editor

Буфер только в UTF-8: `LC_ALL=en_US.UTF-8 pbcopy < файл.sql`, сверить md5. Полный перенос идёт ~6 минут: панель через ~1 минуту показывает ошибку разбора ответа, **запрос продолжает работать** — ждать, пока в `pg_stat_activity` не останется `rbi_transfer_run`, результат — в `quality.rbi_transfer_runs`. Не запускать повторно, пока идёт предыдущий.

## День переключения (P2-0028) — порядок

Старое приложение продолжает работать до переключения и меняет записи (например, задачи — каждые несколько минут). Повторный запуск **добавляет только новые строки**, изменённые не обновляет, поэтому:

1. `05_fingerprint.sql` — отпечаток «до»; `08_size.sql`.
2. Сотрудники уже есть (P2-0028, 25.10.2026: 17 учёток, `09_staff.mjs`); новые — тем же скриптом (повтор безопасен).
3. `06_clear.sql` — строки компании (список файлов не трогается).
4. `03_run.sql` с `null` (полный) — ждать окончания (~6 мин).
5. `node scripts/rbi-transfer/files.mjs copy <id RBI>` — докопирует только новые файлы.
5а. `10_attach_profiles.sql` — профили (рейтинг, награды) к учёткам; без этого у людей «пропадают» рейтинг и награды.
5б. `11_roles.sql` — показ, затем применение (`true`): роли и объекты; ждать «уже так» у всех 17. Затем `12_visibility_check.sql` по порциям — «расхождений: 0».
6. `04_verify.sql` (null) — все `ok`; `07_verify_detail.sql` — все `ok`; `05_fingerprint.sql` «после» — строк столько же (md5 может отличаться только у таблиц, которые меняло работающее старое приложение — проверить по времени изменений).
7. Устройства, которые уже входили в «RBI» до переноса, загружают только изменения — перенесённые записи со старыми датами к ним не придут: на таком устройстве нужна полная загрузка (выход из компании/повторный вход или сброс данных устройства). Новые устройства загружают всё при первом входе.

8. Пароли: сотрудникам выдаёт владелец — «Компания → Сотрудники → Сбросить пароль» (временный, показывается один раз; при первом входе человек придумывает свой).

**Сотрудники (P2-0028, 25.10.2026):** 17 учёток по рабочим почтам (справочник организации Яндекс 360), роли временные до P2-0033 (с 25.10.2026 — роли «как в РБИ» и объекты, `11_roles.sql`); владелец — рабочая почта («Администратор компании»), gmail — только администратор платформы. Перенос заново 25.10.2026: 1610 проверок, у всех автор — учётка; сверка 55/55 и 25/25; `public` до = после.

**Откат:** `files.mjs clear <id RBI>`, затем `06_clear.sql`; старое приложение не затронуто. Миграции — `031c…031_down.sql` в обратном порядке (`031c` → `031b` → `031a` → `031`).
