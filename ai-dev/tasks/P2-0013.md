# P2-0013 — Один вход в Platform 2.0 и модули по компаниям: вход при открытии, меню = модули компании ∩ роль, «Администрирование платформы», отключённый модуль не скачивается

**Статус:** DRAFT (Архитектор, 22.10.2026; ждёт ответов владельца в §8 и утверждения)  
**Владелец продукта:** Igor (IgNiKoN)  
**Репозиторий:** `platform-2-core`, база — `main` `72f7c62` (P2-0012 влит).  
**Ветка:** `task/P2-0013-login-modules` (создаёт Исполнитель после READY).  
**Источник:** ADR-064 (`standards/DECISIONS_2026-10-20.md`, п. 1–4, 6); описание, согласованное с владельцем 22.10.2026 в чате («как будет работать вход», «что скачивается в память телефона»), решения владельца 22.10.2026: делить на P2-0013 (вход и модули) и P2-0013b (люди и пароли); «Компания» — раздел Настроек, не модуль.  
**Зона риска:** CRITICAL — права на сервере (миграция `014`: признак администратора платформы в единой проверке прав). Общие настройки Auth/JWT **не меняются** (ADR-061/061a).  
**Следующая задача:** P2-0013b «Люди и пароли» — администратор компании заводит сотрудника (почта + временный пароль + роль), сбрасывает пароль, смена пароля при первом входе.

## 1. Цель

Человек открывает платформу → экран «Вход» (почта + пароль) → один вход на все разделы Platform 2.0 → в меню только модули, включённые его компании и разрешённые его ролью; модуль, который ему не положен, на устройство **не скачивается**. Владелец как администратор платформы в «Настройки → Администрирование платформы» видит компании, создаёт компанию и включает/выключает ей модули. Работники РБИ со старым входом по PIN уходят кнопкой в боевой Quality — он не меняется.

## 2. Подтверждённое исходное состояние (22.10.2026, только чтение)

- Открытие оболочки: окно `#auth-gate-overlay` (`index.html`) — «Работать локально» / «Войти в облако» (старый облачный вход Quality в этой копии отключён с P2-0002: `CLOUD_DISABLED_MESSAGE`). Почта + пароль спрашивается **внутри** «План/Факт» (`PlanfactApp.ts`, «Вход в План/Факт»); сессия Supabase общая для «План/Факт» и «Компании» (`src/platform/auth/auth.service.ts`).
- Меню модулей Platform 2.0: `app-shell.js getPlatformMenuItems()` — пункты манифестов `section: 'platform'` + `requiresAccess` по флагам `window.RBI.platformMenuAccess` (ставит раздел по ответу сервера). В боковом меню этой копии видны и пункты старого Quality (локальные, к боевым данным не подключены).
- Загрузка: `js/modules/planfact/index.js` **статически** импортирует `js/dist/planfact/planfact.js` (≈1,4 МБ, внутри React) — модуль скачивается всем при открытии; так же `company.js` (≈1 МБ, своя копия React). `exceljs` — лениво. `sw.js`: бизнес-бандлы Quality/Стройконтроля кэшируются только по списку разрешённых (`RBI_SW_ALLOWLIST`), запрещённые удаляются; бандлы Platform 2.0 под это правило **не попадают**.
- Сервер: `planfact.company_modules(company_id, module, enabled)` есть (002), при создании компании включается `planfact`; `has_permission` / `has_company_permission` уже требуют включённый модуль `planfact`. Признака «администратор платформы» нет; экранов управления компаниями и модулями нет; компании создаются SQL-скриптом.
- Размещение: GitHub Pages `https://ignikon.github.io/platform-2-core/` (решение владельца 22.10.2026), тестовые учётки на 9 ролей в «Демо-компании».

## 3. Объём реализации

1. **Сервер (миграция `014`, только добавление):** `planfact.platform_admins(user_id)` (без доступа клиенту), `planfact.module_catalog(code, name)` — пока один модуль `planfact`; признак администратора платформы в `planfact.has_permission` / `has_company_permission` / `is_project_member` (ADR-064 п. 6 — **одна** проверка, не разрозненно); функции: `pf_my_platform()` — кто я: администратор платформы ли, мои компании и **доступные мне модули по каждой** (модули компании ∩ права); `pf_platform_companies()`, `pf_platform_create_company(name)`, `pf_platform_set_module(company, module, enabled)`, `pf_platform_set_company_admin(company, email)` — только администратору платформы, каждое изменение — в журнал (`audit_log`). Назначение владельца администратором платформы — отдельный SQL, выполняет владелец (почта — §8).
2. **Вход при открытии:** вместо окна «Работать локально / Войти в облако» — экран «Вход»: почта, пароль, «Войти»; ниже кнопка «Качество и Стройконтроль — вход по PIN» (ведёт в боевой Quality, адрес — §8) и мелкая ссылка «Посмотреть без входа (демо)» (нынешний локальный режим: разбор ВОР без сохранения). Вход запоминается на устройстве; «Выйти» — в «Настройки → Платформа» (и в полосе «почта · компания · роль»). Если человек в нескольких компаниях — переключатель «Компания: …» в шапке; меню перестраивается. «Вход в План/Факт» внутри модуля убирается (при неактивной сессии — экран «Вход»).
3. **Меню по модулям:** после входа меню = модули из `pf_my_platform` для выбранной компании (+ «Настройки»); пункты старого Quality в этой копии вошедшему почтой не показываются; адрес выключенного модуля → понятное сообщение «Модуль не подключён вашей компании». Подвкладки модуля — по правам, как сейчас.
4. **Не скачивать неположенное:** бандлы `planfact` и `company` подгружаются динамически только после входа и только при доступе (`planfact` — модуль доступен; `company` — право `security.roles.assign` или администратор платформы); `sw.js` — те же правила кэша/удаления, что у Quality, для `js/dist/planfact/`, `js/dist/company/`. Человек без доступа (и вход по PIN / демо) этих файлов не получает; выключили модуль — файлы удаляются после обновления.
5. **«Настройки → Администрирование платформы»** (только администратор платформы; сервер проверяет каждый вызов): список компаний (название, тестовая ли, число людей, модули), «Создать компанию», выключатель модуля у компании, «Назначить администратора компании» (по почте **существующей** учётки; создание учёток — P2-0013b). Подвкладки в стиле Настроек, адрес `#/settings/platform-admin`.

**Вне блока:** создание учёток людей, временный пароль, сброс пароля, смена пароля при первом входе (P2-0013b); сброс пароля письмом (отдельное решение по Auth); подключение старого Quality к компаниям (этап «Quality в Platform 2.0»); одна общая копия React для бандлов (ТД); переключение «админ платформы видит всё» → модель SaaS (пункт ROADMAP перед продажей).
