# P2-0032 — День переключения РБИ на Платформу 2.0 (заготовка — решения владельца; карточка пишется после P2-0031)

**Статус:** ЗАГОТОВКА · 25.10.2026 (Архитектор). Не для исполнения до приёмки P2-0028, P2-0033, P2-0031.
**Основание:** ADR-069 п. 5, 7; `docs/RBI_TRANSFER.md` (P2-0027); замечания приёмки P2-0027.

## Решения и требования владельца (накопленные, 25.10.2026)

1. **Порядок дня:** все синхронизируют старое приложение → финальный перенос в «RBI» (очистка + полный, `docs/RBI_TRANSFER.md`) → сверка → выкладка кода Платформы 2.0 туда, откуда открывается старое приложение (откат — прежняя версия по метке) → вход по PIN выключен → **открытая регистрация на сервере закрыта** (разрешение владельца на изменение настройки Auth — отдельно, ADR-061a) → владелец выдаёт временные пароли кнопкой «Сбросить пароль».
2. **Загрузка на устройствах — без дублей, полная замена один раз** (владелец 25.10.2026: «данные не должны дублироваться, полностью заменить старые новыми единоразово»):
   - при первом запуске новой версии на устройстве со старыми данными РБИ — найти неотправленное в старой локальной базе (черновики, проверки «не отправлено», очередь); отправить или показать «у вас N неотправленных» и не терять;
   - затем новая база устройства (своя для компании/учётки) загружается **полностью одним разом**; записи с теми же id заменяются, а не добавляются;
   - после успешной загрузки старая локальная база и кэш старого приложения **удаляются один раз автоматически**;
   - устройства, уже загружавшие «RBI» до финального переноса, — принудительная полная загрузка один раз (ТД №176).
   - Проверка на телефоне: до — старое приложение с данными и одним неотправленным черновиком; после — новые данные целиком, черновик не потерян, дублей нет (числа «Истории» = сверке), старая база удалена.
3. **Очередь отправки РБИ** (`rbi_sync_queue`, 1849) и журнал ошибок (`rbi_error_logs`, 2847) — проверить, что новое приложение не повторяет старую очередь; при сомнении — не переносить в финальном переносе (замечание приёмки P2-0027).
4. **Сверка действий «старое ↔ новое»** тестовой учёткой инженера до выдачи паролей: создать проверку с фото, СК, задачи, сформировать отчёт, База знаний.
5. **Памятка сотрудникам** (1 страница): как войти, первая смена пароля, что изменилось.
6. После перехода — удаление со старого сервера готовых отчётов (`shared_report_snapshots`, бакет `reports`) — владельцем, с архивом (ADR-069 п. 3).
